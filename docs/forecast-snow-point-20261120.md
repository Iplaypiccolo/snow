# 신적설을 날씨누리와 같게: 단기 칸 조회 + 앞 6시간 계산 (2026-11-20)

목적: 사용자 원칙 "기상청(날씨누리)과 동일한 예보·특보 값". 11/18~20 눈 오는 동안 모은 자료로 어디가 왜 다른지, 어떤 자료를 어떻게 받으면 같아지는지 정리한다.
상태: 분석 끝(11/21 새 자료로 다시 확인), 측정 정리 끝(104). 화면·수집은 아직 바꾸지 않음. 아래 "단계" 1번부터 사용자 승인 뒤 진행.

## 1. 확인한 사실

### 1-1. 기상청 자료 창구별 값 (11/19 확인)
| 창구 | 한 번 부르면 | 신적설 | 강수 |
|---|---|---|---|
| 단기 격자 `nph-dfs_shrt_grd` (지금 씀) | 전국 한 시각·한 종류 (약 340KB) | 정수. 1cm 미만 = 0, 그 위 반올림 | 정수. 1mm 미만 = 0 |
| 단기 칸 조회 `VilageFcstInfoService_2.0/getVilageFcst` (11/19 활용신청) | 칸 하나 × 약 4일 × 전 종류 (약 135KB, 800~1,016줄, `numOfRows=1100` 이면 한 번에) | **소수 한 자리, '0.5cm미만', '적설없음'** | '1mm 미만', '1.0mm'(정수) |
| 초단기 격자 `nph-dfs_vsrt_grd` (지금 씀) | 전국 한 시각·한 종류 | 없음 | 정수 |
| 초단기 칸 조회 `getUltraSrtFcst` (11/19 활용신청) | 칸 하나 × 6시간 | 없음 | '1mm 미만', '1.0mm' |

- 단기 칸 조회 값 = 격자 값의 원래 값: 2.9→3, 1.5→2, 1.4→1, 0.9·0.8·0.6→0 (11/19 17시 발표 3칸).
- 단기 칸 조회 시각: 3일째까지 1시간 간격, 4일째는 3시간 간격. 1시간 표 끝까지는 모두 1시간 간격.
- 신적설 > 0 은 격자 강수형태 '비/눈'(2)·'눈'(3) 시각에만 나옴(17시 발표 전 칸·시각: 없음 141,269·비 12,085 에서 0, 비/눈 7, 눈 369).

### 1-3. 앞 6시간 신적설 계산 (날씨누리 8회차, 앞 6시간 2,064칸·시각, 숫자 744개)
자료: 11/19 17·18시, 11/20 00·01·03·04·05·06시 예약 대조(kma-forecast-compare-2)가 남긴 날씨누리 원래 페이지. 날씨누리 앞 6시간 기온·강수·날씨 이름은 같은 발표 초단기 API 값과 100% 같아 페이지 값을 API 값으로 씀.
- 표시 여부: **초단기 강수형태 '눈'(3) + 기온 0℃ 이하 → 숫자, 아니면 '-'** = 2,025/2,064 (98.1%).
  어긋난 39곳은 0℃·'~1mm' 인데 '-' 25곳, 1℃ 인데 숫자 14곳(1℃ 칸 50곳 중 14곳에 숫자). -1℃ 이하 눈은 늘 숫자, 2℃ 이상·'비/눈'·'눈날림'은 늘 '-'.
- 숫자 크기(회차 하나씩 빼고 맞춘 뒤 빠진 회차로 시험):
  | 방법 | 정확히 같음 | 0.6cm 안 |
  |---|---|---|
  | 늘 0.6 | 50% | 77% |
  | 강수(가운데 값: '~1'=0.5, r=r+0.5) × 기온별 비율(0℃ 0.6, -1℃ 0.8, -2℃ 이하 1.1) → 0.6 단위 반올림(최소 0.6, 3.0 이상 '3~') | 69% | 99% |
  | (강수, 기온)별 가장 흔한 값 표 | 72% | 99% |
  같은 강수·기온에서 날씨누리 값이 두 칸(예 0.6/1.2)으로 갈려, 정수 자료로는 약 72% 가 한계. 기상청은 소수 강수·기온으로 셈하는 것으로 봄.
- 지금 우리 화면(앞 6시간에도 단기 신적설)은 눈 있다·없다부터 자주 다름(11/20 00시 회차 50곳 중 22곳).
- **새 자료로 다시 확인(11/21)**: 11/20 15시~11/21 14시 예약 대조 118개 발표·147칸, 앞 6시간 6,113칸·시각(위 계산을 만들 때 쓰지 않은 자료).
  | 확인 | 결과 |
  |---|---|
  | 표시 여부(눈 + 0℃ 이하) | 5,961/6,113 (97.5%). 어긋남: 0℃·'~1' 인데 '-' 58, 1℃ 인데 숫자 94 |
  | 숫자 크기, 위 계산식(비율 0.6·0.8·1.1) 그대로 | 847개 중 정확히 같음 610 (72%), 0.6cm 안 843 (99.5%) |
  | 숫자 크기, 옛 자료로 만든 표 | 614 (72.5%) |
  | 늘 0.6 | 505 (60%) |
  | 모든 자료(1,591개)를 보고 만든 표가 낼 수 있는 최대 | 1,172 (74%) |
  눈 아닌 날씨 이름에 숫자가 나온 적 0. 주로 틀리는 곳: 강수 1mm·0℃(날씨누리 0.6/1.2 반반), '~1'·영하 1~2℃(0.6/1.2).
- 3시간 표 강도 이름: "그 3시간 1시간 표에 신적설 숫자가 있으면 눈 이름, 비·빗방울이 섞이면 비 이름도" 가 밤새 회차마다 거의 전부 맞음(예 11/20 01시 72/72).

### 1-4. 칸 조회 안정성 측정 (마이그레이션 103, 11/19 23시~11/20 23시 발표 27회 × 40칸, 11/21 104 로 정리)
- 발표 11분 뒤에는 모든 회차에 새 발표가 받아짐(그보다 이른 시각은 안 재 봄).
- 1,080번 중 1,072번 성공(99.3%). 실패 8번은 모두 응답 없음·시간 초과(25초) — 다시 부르면 되는 종류. 기상청 오류 응답 0.
- 칸당 평균 1.1~1.9초가 보통. **11/20 23:20 회차만 느림: 평균 10.1초, 40칸 중 24칸이 5초 넘음, 2칸 25초 시간 초과**(23:11 은 평균 2.7초·최대 8.1초).
  → 기상청이 느린 때가 있으므로 화면은 칸 조회를 기다리지 않고 앞 발표 값(없으면 격자 값)을 먼저 보여야 함(2의 ④).

## 2. 받는 방법 (사용자 11/19 결정: 연 기관만 칸 조회)
| 자료 | 받는 방법 |

| 단기 신적설·강수(6시간 뒤~) | **기관(지사)을 열 때 그 지사 격자만 단기 칸 조회**. 같은 발표 동안 저장해 다시 씀 |
| 단기 격자 | 지금 그대로(전국·본부 지도, 칸 조회 실패 때 대신 씀) |
| 일별 보강·중기·특보·적설 관측 | 지금 그대로. 정각 초단기 건너뛰기·일별 보강 먼 날도 그대로(사용자 "그대로") |

칸 조회 장치: ① 같은 칸은 한 번만(여럿이 열어도 기상청 1번) ② 서버 전체 동시 8개까지 ③ 최근 며칠 연 지사는 발표 11분 뒤 미리 받기 ④ 새 값이 오기 전·실패 때는 앞 발표 값(그것도 없으면 격자 값) ⑤ 실패 칸은 다음 회차에 다시 ⑥ 칸 조회 사용량을 따로 셈(일별 보강도 함께 세기 시작).
예상: 하루 10개 지사를 열면 약 +2,000회(최대 +12,300회).
