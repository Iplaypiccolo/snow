# 일별 창 가까운 날 오전/오후 = 격자 시간별 값 요약 (2026-11-09, 마이그레이션 84)

사용자 결정 "가안으로 하자"(2026-11-09). 그 전까지는 단기 육상예보의 지역 대표값(11/7 결정)을 썼다.

## 기상청 날씨누리가 하는 방식 (대조로 찾음)
날씨누리 동네예보 화면(`/w/wnuri-fct2021/main/digital-forecast.do?code=…&lat=…&lon=…`)은 **시간별 표와 가까운 날 일별 칸이 좌표(격자) 기준**이고, **중기(5일째~)는 지역 코드 기준**이다(같은 코드로 좌표만 바꾸면 중기는 그대로, 코드를 바꾸면 중기만 바뀜).

| 항목 | 규칙 |
|---|---|
| 구간 | 오전 = 01~12시, 오후 = 13~24시의 1시간 값 12개(그 시각까지의 값) |
| 강수확률 | 강수형태>0 시각이 있으면 12시간 최고, 없으면 평균을 10% 단위 반올림(5는 올림) |
| 하늘 | 맑음1·구름많음2·흐림3(SKY 1·3·4) 평균을 반올림 |
| 비 문구 | 오는 시각 1~2 "한때 비", 3~5 "가끔 비", 6 이상 "비 계속" |
| 최저·최고 | 공식 TMN/TMX(격자) — 이미 같은 값을 쓰고 있었음 |

## 표본과 결과 (단기 11:00 발표, 1,538칸 중 무작위)
- 규칙 찾기 60칸 + 따로 검증 50칸. 기준: 반나절 300개 무오류면 "틀리는 비율 1% 미만"을 95%로 말할 수 있음(3/n).
- 11/10~11 강수확률·하늘: 찾기 240/240, 검증 200/200(하늘은 날씨누리 시간별 아이콘으로 확인).
- 강수확률을 우리 서버 시간별 자료로 계산: 11/10~12 반나절 660개 중 651개 일치(98.6%). 같은 660개에서 예전 지역 대표값은 577개(87.4%).
- 틀린 9개는 모두 4일째(11/12) 오전의 10%/0% 경계. 시간별 확률이 똑같은 칸끼리도 날씨누리 결과가 갈림 → 날씨누리는 10% 단위로 반올림하기 전 값을 쓰는 것으로 보이며, 우리 자료로는 재현 불가.
- 4일째 23시는 기상청이 전 칸 0으로 주는 빈 시각. 빼고 평균하든 0으로 넣든 110칸 결과가 같았음 → 빈 시각은 빼고 계산.

## 확인 못 한 것
- 비 오는 반나절이 가까운 날에 2개뿐(둘 다 일치). 비 문구 기준은 오늘 오후 비 28칸에서 찾았으나 그 칸은 지난 시각이 빠져 있었음.
- **눈·비/눈·소나기 문구**는 표본 없음(눈 예보 없는 날). 지금은 "한때 눈", "가끔 비/눈", "눈 계속"처럼 같은 틀로 만듦. 눈 예보가 있는 날 다시 대조해야 함.
- **오늘 칸**: 날씨누리는 지난 시각도 넣어 계산하는데 그 값의 출처를 모름. 우리는 최신 발표에 남아 있는 시각만으로 계산. 오늘 최저·최고도 날씨누리와 다름(관측·실황 섞는 것으로 추정, 미확정).

## 서버 동작 (84)
- `private.kick_daily_aux`: SKY도 받음(`sky:true`). 예약 `collect-daily-aux` 20분 → 10분 간격. 단기 발표마다 SKY 약 85번 추가(하루 약 680번·230MB).
- `forecast_daily_cell`: 최신 완료 단기 발표의 POP·PTY + 시각별 최신 SKY(새 발표 SKY가 다 오기 전엔 앞 발표 값)로 반나절 계산. 12시간이 다 있는 반나절만(오늘은 끝나지 않은 반나절이면 있는 시각만). SKY가 빠진 반나절은 예전처럼 지역 대표값 → 중기. 응답 모양 같음, `source:'short_grid'`, `hours`, `sky_issued_at` 추가. 화면 코드 변경 없음.
- `forecast_version` d 에 단기 발표 완료 시각 추가 → 새 발표가 끝나면 열린 일별 창도 다시 받음.
